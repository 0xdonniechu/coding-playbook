# Internals: how each hook and script works

Moved verbatim from `CLAUDE.md` (2026-11-11) so sessions in this repo do not load it on every turn. `CLAUDE.md` keeps the rules and one line per item; read the section here before changing that item.

## `graph/graph-hook.py`

`graph/graph-hook.py`: the session graph. SessionEnd only starts `refresh <top>` detached (a transient `systemd-run --user` service with `MemoryMax=4G` and `RuntimeMaxSec=900`; a failing `systemd-run` starts nothing; without systemd, as on macOS, a new process session), because Claude Code gives a SessionEnd hook a short budget; the job holds `<git dir>/progress-diagram/refresh.lock`, skips when HEAD, `git diff HEAD` and the untracked names are as last time, and replaces `overview.md` and `architecture.html` only after both were written whole, so a failing tool keeps the old graph and records the error in `session-graph.json`. A state whose refresh failed, or whose job died twice, is not tried again until the work tree changes. SessionStart prints two lines naming the files, the commit and how far HEAD moved, never the overview itself. It writes only into the git folder, always exits 0, and runs with `|| true`.

## `loop/loop.py` and `loop/loop-stop.py`

`loop/loop.py` and `loop/loop-stop.py`: the one-prompt run. Done rests on evidence: the Stop hook judges with `sdlc-check.py converge --checks`, which runs each task's `check:` commands through the shell once nothing else is missing, each in its own process group that a timeout kills whole (900 s each, 1500 s for all, the hook has 1800 s), and the third round with a failing check closes the run (`checks`; the count starts again at `resume`). The SubagentStop mode (`loop-stop.py subagent-stop`) records the first PASS or FAIL word of every run of an agent whose type ends in `reviewer` in the run's `reviews`, for each plan task named on a line of its prompt (the first user message of its transcript) that starts with `loop task: T<n>` or `loop tasks: T1, T2` (spaces, `>`, `*`, `-`, `_`, `#` and backticks may come first, and the ids before the first other word count; a phrase quoted inside a sentence never counts); a verdict that names no task of the plan counts for nothing. `loop.py pass <task>` is refused unless that task's last verdict is PASS, and done is refused while a task's last verdict is FAIL, while a task has a reviewer FAIL with no `loop.py fail`, or with no PASS for any task when a Proof item names a review. Limits, on purpose: a `loop.py fail` is counted for its task whatever verdict it answered, and the run file is a plain file the session could edit; this guards against haste, not against cheating. `start --hours <n>` (default 12) sets a time limit the hook enforces. A run closed by ask, two fails, idle, a limit or checks is commented once on the plan's `Plane <KEY-N>` ticket (`plane.py` beside the judge, waited for 30 s at most: a session woken by `loop-wake.py` runs in a systemd unit that kills a detached child when it ends). A session in permission mode `default` is told once that it will wait at unknown commands. While a subagent of the session runs in the background (the Stop input's `background_tasks`, type `subagent`) the hook gives no decision and counts nothing, 10 stops in a row at most, so waiting for a reviewer never closes a run as idle (found by the first live run, 2026-11-11); a background shell is not waited for, because one that never ends would leave the run open with nobody told. A check's output stays in the run file: the ticket comment names the task and the command only. `loop.py start <plan>` writes `<git dir>/1prompt-run.json`, bound to the session that started it (`CLAUDE_CODE_SESSION_ID`); `~/.claude/1prompt-runs/<session id>` points the hook at it wherever the session's cwd is. The Stop hook blocks that session's stop while `sdlc-check.py converge` lists a gap, a proof result is a FAIL or a task's review FAIL has no later PASS; it closes the run as done only on the judge's own PASS verdict (a crash, a timeout or other output is never done), after the second FAIL of one task (`loop.py fail`), on `ask` or `stop`, after 3 stops with no change in HEAD, the content of the work tree, the plan or the verdicts, or after 40 stops held. An error inside the hook lets the session stop (a judge failure holds it, bounded by the breakers), and its command ends in `|| true` (exit 2 from a Stop hook would keep it going). Limits: one run per work tree and one open run per session; the breakers count stops, not time; untracked files are hashed up to 1 MB each.

## `loop/loop-wake.py`

`loop/loop-wake.py`: wakes a run whose session died. A systemd user timer (`loop-wake.py install`, run by hand once per machine from the installed copy `~/.claude/hooks/loop/`; refused from a checkout) runs `tick` every 10 minutes. A running run whose session has been quiet 30 minutes (transcript and subagent files unchanged, no live `busy` record in `~/.claude/sessions/`, no unit of any of its wakes running, and a `systemctl` that cannot answer counts as running: a headless session writes no record) is forked headless (`claude -p --resume <old> --fork-session --session-id <new> --settings ~/.claude/hooks/1prompt/autonomous-settings.json`, the session's cwd and model, the permission mode the Stop hook recorded as `mode` or else the transcript's last), after the run is bound to the new id; the fork runs in its own systemd unit (MemoryMax 8G, runtime up to the run's time limit). Caps: 4 wakes per run, waits of 30, 60, 120 min, the run's time limit, $50 of wake spend a day: each wake reserves at most $20 (`--max-budget-usd`) in `~/.claude/1prompt-runs/.wake-spend.json` before it starts, and the child turns the reservation into the real cost on the reservation's day (a child killed early, or an output without its cost, keeps the whole reservation). A cap closes the run (`limit`). Every wake and close is commented on the plan's ticket (synchronously: the timer's service would kill a detached comment); a run in a mode that asks, or with no boundary settings, is never woken, and the ticket is told once. A wake whose unit never started is woken again from its source after 30 quiet minutes. `loop.py resume` resets the wakes and binds the run to the resuming session. A ledger that cannot be read counts as the day's cap reached; when `systemctl` cannot answer, `tick` says so and wakes nothing. Limits: Linux with systemd only; a session that is alive but idle is forked too, so the owner's old window no longer holds the run.
