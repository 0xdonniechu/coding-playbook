## `saveit/saveit-hook.py`

`saveit/saveit-hook.py`: the save-it hooks for every session. SessionStart prints `ambysto-saveit resume` into context only when the repo root has a `HANDOFF.md`; PreCompact runs `ambysto-saveit tail --write` only into an existing UTF-8 `HANDOFF.md` that git ignores and does not track (the tail copies commands as typed, keys included); it never creates the file. It always exits 0, and its `settings.json` command ends in `|| true` so even a missing file cannot exit 2 (which refuses a compaction); it does nothing without the binary or outside a git work tree.

## `graph/graph-hook.py`

`graph/graph-hook.py` (APS-57): the session graph. SessionEnd only starts `refresh <top>` detached (a transient `systemd-run --user` service with `MemoryMax=4G` and `RuntimeMaxSec=900`; a failing `systemd-run` starts nothing; without systemd, as on macOS, a new process session), because Claude Code gives a SessionEnd hook a short budget; the job holds `<git dir>/progress-diagram/refresh.lock`, skips when HEAD, `git diff HEAD` and the untracked names are as last time, and replaces `overview.md` and `architecture.html` only after both were written whole, so a failing tool keeps the old graph and records the error in `session-graph.json`. A state whose refresh failed, or whose job died twice (killed at the time limit, out of memory, a logout), is not tried again until the work tree changes. SessionStart prints two lines naming the files, the commit and how far HEAD moved, never the overview itself. It writes only into the git folder, always exits 0, and runs with `|| true`.

## `loop/loop.py` and `loop/loop-stop.py`

`loop/loop.py` and `loop/loop-stop.py` (APS-56, APS-58): the one-prompt run. Done rests on evidence: the Stop hook judges with `sdlc-check.py converge --checks`, which runs each task's `check:` commands through the shell once nothing else is missing, each in its own process group that a timeout kills whole (900 s each, 1500 s for all, the hook has 1800 s), and the third round with a failing check closes the run (`checks`; the count starts again at `resume`). The SubagentStop mode (`loop-stop.py subagent-stop`) records the first PASS or FAIL word of every run of an agent whose type ends in `reviewer` in the run's `reviews`, for each plan task named on a line of its prompt (the first user message of its transcript) that starts with `loop task: T<n>` or `loop tasks: T1, T2` (APS-61; spaces, `>`, `*`, `-`, `_`, `#` and backticks may come first, and the ids before the first other word count; a phrase quoted inside a sentence never counts); a verdict that names no task of the plan is kept with no task and counts for nothing, so a review of other work in the same session, given no marker as the instructions say, does not pass the run (seen live: an APS-60 PASS landed in the APS-59 run). A verdict, and an open review FAIL, count only while the plan still has the task. `loop.py pass <task>` is refused unless that task's last verdict is PASS, and done is refused while a task's last verdict is FAIL, while a task has a reviewer FAIL with no `loop.py fail`, or with no PASS for any task when a Proof item names a review. Limits, on purpose: the run file is a plain file the session could edit; a `loop.py fail` is counted for its task whatever verdict it answered; this guards against haste, not against cheating. `start --hours <n>` (default 12) sets a time limit the hook enforces. A run closed by ask, two fails, idle, a limit or checks is commented once on the plan's `Plane <KEY-N>` ticket (`plane.py` beside the judge, waited for 30 s at most: a session woken by `loop-wake.py` runs in a systemd unit that kills a detached child when it ends). A session in permission mode `default` is told once that it will wait at unknown commands. While a subagent of the session runs in the background (the Stop input's `background_tasks`, type `subagent`) the hook gives no decision and counts nothing, 10 stops in a row at most, so waiting for a reviewer never closes a run as idle (found by the first live run, 2026-11-11); a background shell is not waited for, because one that never ends would leave the run open with nobody told. A check's output stays in the run file: the ticket comment names the task and the command only. `loop.py start <plan>` writes `<git dir>/1prompt-run.json`, bound to the session that started it (`CLAUDE_CODE_SESSION_ID`); `~/.claude/1prompt-runs/<session id>` points the hook at it wherever the session's cwd is. The Stop hook blocks that session's stop while `sdlc-check.py converge` lists a gap, a proof result is a FAIL or a task's review FAIL has no later PASS; it closes the run as done only on the judge's own PASS verdict (a crash, a timeout or other output is never done), after the second FAIL of one task (`loop.py fail`), on `ask` or `stop`, after 3 stops with no change in HEAD, the content of the work tree, the plan or the verdicts, or after 40 stops held. Its writes keep a `stop` or verdict written while the judge ran. `start` refuses a plan without `## Tasks` and `## Proof`, a plan outside the cwd's tree and a base that is the branch being worked on. An error inside the hook lets the session stop (a judge failure holds it, bounded by the breakers), and its command ends in `|| true` (exit 2 from a Stop hook would keep it going). Limits: one run per work tree and one open run per session; the breakers count stops, not time; untracked files are hashed up to 1 MB each.

## `loop/loop-wake.py`

`loop/loop-wake.py` (APS-59): wakes a run whose session died. A systemd user timer (`loop-wake.py install`, run by hand once per machine from the installed copy `~/.claude/hooks/loop/`; refused from a checkout) runs `tick` every 10 minutes. A running run whose session has been quiet 30 minutes (transcript and subagent files unchanged, no live `busy` record in `~/.claude/sessions/`, no unit of any of its wakes running, and a `systemctl` that cannot answer counts as running: a headless session writes no record) is forked headless (`claude -p --resume <old> --fork-session --session-id <new> --settings ~/.claude/hooks/1prompt/autonomous-settings.json`, the session's cwd and model, the permission mode the Stop hook recorded as `mode` or else the transcript's last), after the run is bound to the new id; the fork runs in its own systemd unit (MemoryMax 8G, runtime up to the run's time limit). Caps: 4 wakes per run, waits of 30, 60, 120 min, the run's time limit, $50 of wake spend a day: each wake reserves at most $20 (`--max-budget-usd`) in `~/.claude/1prompt-runs/.wake-spend.json` before it starts, and the child turns the reservation into the real cost on the reservation's day (a child killed early, or an output without its cost, keeps the whole reservation). A cap closes the run (`limit`). Every wake and close is commented on the plan's ticket (synchronously: the timer's service would kill a detached comment); a run in a mode that asks, or with no boundary settings, is never woken, and the ticket is told once. A wake whose unit never started is woken again from its source after 30 quiet minutes. `loop.py resume` resets the wakes and binds the run to the resuming session. A ledger that cannot be read counts as the day's cap reached; when `systemctl` cannot answer, `tick` says so and wakes nothing. Limits: Linux with systemd only; a session that is alive but idle is forked too, so the owner's old window no longer holds the run.

## `guard/owner-token-guard.py`

`guard/owner-token-guard.py` (APS-37): a PreToolUse hook for every session. It denies a command or a Read/Grep/Glob that would take the owner's GitHub token (`gh auth token`, `--show-token`, `auth switch`/`logout`/`refresh`, `git credential fill`/`get` and running a credential helper, `gh alias set`/`gh extension install`, git's credential traces, gh's config folder, the keyring) and asks the owner to confirm any command that sets `AMBYSTO_OWNER`. It catches mistakes and casual use, not a script file that reaches the keyring; the wrapper and credential helper read the token outside the agent's tools and are not seen.

## `hooks/autonomous-settings.json` (boundary mode)

`hooks/autonomous-settings.json` (APS-34) runs `agent-guard.py` in boundary mode before and after every tool call of an autonomous run and at each stop (main session and subagents). Two layers, as in APS-32. **Before** a call it reads the command line and blocks the human-only list (tags, releases, publishing, signing and keys, force push, remote deletes, pushes to main, `bd` outside its allowlist) and the usual writes to protected paths; that layer catches mistakes, not evasion (shell wildcards, interpreters and scripts get past it). **After** every call it compares the protected paths of each git tree the run touched (status, diff from HEAD and staged blobs, so an edit, a new file, a delete or a commit all show) and the guard's own files in `~/.claude` with a snapshot; any change, by any writer, is reported at once, from then on only reading and `bd` (to park the bead) run, and the run's report must start with `PROTECTED CHANGED:`. Its limits: it detects after the fact rather than preventing; files git ignores are not watched; MCP tools are checked only by the after layer. Protected paths are judged against a trusted base: `base` in the project's `.claude/boundary.json` (for a long-lived branch; the file is protected, so only the owner sets it), else `origin/HEAD`, `origin/main` or `origin/master`; never the branch's own upstream or a local branch, which the run can move. A branch's own protected changes are the uncommitted ones plus those committed since it forked from that base: a run that starts on any is flagged from its first call, a push that would carry any is blocked, and a pull, merge or rebase that brings in only the base's changes is not a write. Without a trusted base (no remote fetched) every protected change after the start is reported. Bases are read by their full names (`refs/remotes/origin/…`, so a local branch called `origin/main` does not count), a configured `base` must be a remote branch, a branch with no common history with the base counts as changed, and every branch a push names is checked, not only HEAD. The usual ways to move the base are blocked (`git update-ref`, `replace`, `symbolic-ref`, `remote` writes, `branch -f/-m/-D` on main or remote branches, fetch and pull refspecs or `--refmap`, `push .` or into `refs/remotes`, `-c remote.…`, `git config` of remotes, branches, hooks or includes). This is still a mistake guard: the hook runs as the same user as the agent, so an agent that sets out to fake the local repository (an interpreter writing into `.git/`) can get past it, and a write, commit and push in one command is reported only after that push. The firm boundary is on GitHub: a ruleset on main and CODEOWNERS review for protected paths, by an owner identity the agent does not hold. The lock lasts for the rest of the session, across stops. A folder that holds a protected path counts as protected, so `git restore .` and `rm -rf .` are blocked; restore by file. Spending and new paid services are not detectable by command (the cost cap covers spend); `~/.claude.json` (the tracker key) is not a secret here; `gh pr merge` stays open until the merge step of decision 1 exists, a push to main does not. `bd close` reads the bead with `bd show` and blocks unless that exits 0 with this bead's JSON (a short id beads resolves is accepted); priority, deferral and the `optional` label stay the owner's. The stop hook reads the report (`last_assistant_message`) and asks for the line only when it is missing. Trees named only through a relative path (`python3 -c "open('../other/docs/spec/x', 'w')"`) are not watched until the run names them; and a change may already be committed and pushed to a feature branch in the same call that reports it (the lock stops what follows, not that call). The project's own `.claude/settings*.json`, hooks and agents are protected paths by default.

## `hooks/agent-guard.py` (builder and reviewer limits)

`hooks/agent-guard.py` (APS-32) blocks the builder's and the reviewers' git and gh writes by reading the command line: it catches mistakes, including writes after `then`/`do`, a heredoc fed to a shell and `git -c alias.…`, not evasion (known gaps: process substitution `<(…)`/`>(…)`, `coproc`, a script file or an interpreter one-liner such as `python3 -c` that runs git, `git --config-env=alias.…`, and git subcommands not on its lists such as `lfs push`, `svn dcommit`, `send-email`, plus `read-tree`/`update-index` for reviewers; harmless `gh --version`/`gh help` are blocked), and an MCP tool (an issue tracker's) is not covered; `gh api graphql -f` is blocked even for a read query. A reviewer's file changes are found by comparing each git work tree it touches (its cwd, path arguments, absolute paths and `cd` targets in its commands) before and after: files git ignores are not watched, and a tree reached only through a relative path from another tree is missed. The watch sees every change to a tree, so a reviewer that reads a tree another session is editing gets a `TREE CHANGED` line it did not cause (seen 2026-10-22 on the Gate repo); the line says what changed, and the main session judges who. Every git tree a command names is snapshotted, untracked files hashed in full, so naming a large tree (a home folder that is a repo) slows each call and a git call over 60 s blocks it; an unreadable untracked file is tracked by size and time. Reviewers cannot run tree-changing git even in a scratch folder. A missing `python3` lets every call through (exit 127 is not a block); a missing script blocks every call. On Windows the hook command assumes `python3` on the hook shell's PATH and the command line is read as POSIX shell; not tested there yet.

## `scripts/cost-report.py`

`scripts/cost-report.py` (APS-64): cost per role, ticket, model, day or project from the transcripts under `~/.claude/projects` (`<project-dir>/<session>.jsonl` is role `main`; `<session>/subagents/agent-<id>.jsonl` takes its role from `agent-<id>.meta.json` `agentType`, `unknown` without one). An API response is written as several lines (one per content block) with one `message.id` and one usage: it is counted once, by `message.id`, else `requestId`, across all files (a repeat with a larger `output_tokens` replaces the earlier one). Lines that are not JSON, have no usage or model `<synthetic>` are skipped. Price per response = input, output and cache read from `scripts/model-prices.json` plus cache writes at the file's multipliers of input (5 minute 1.25, 1 hour 2.0); cache-creation tokens with no 5m/1h breakdown count as 5 minute writes. A model missing from the table keeps its tokens, shows `?` and is named in the total line; no price is invented. `claude-haiku-5-5` cache read is an assumed 0.1x input (`assumed` in the file); the table is a copy of the API skill's model table cached 2026-11-03, so update it when prices change.

Ticket attribution never guesses: the line's `gitBranch` matching `^([a-z]+)-(\d+)\b` gives `KEY-N`; else, for a subagent, the last `KEY-N` in its meta `description`; else `-`, and the unattributed share is always printed. Limits, on purpose: a main session's ticket comes only from the branch of the `cwd` it was in when the line was written, so work done in another repo through `cd` counts as that branch's ticket or as unattributed, and a branch with a prefix such as `ambysto/aps-62-x` is unattributed; a subagent whose branch carries a ticket uses it even when its description names another. A line with no timestamp is left out of any run with `--since` or `--until` and counted in a note (`no_timestamp` in `--json`); in `--json` a group with no priced response has `"usd": null` and its `unpriced` count. Day is the UTC date of the line's timestamp, project the `cwd` basename (the project dir name when absent). Tokens are billed tokens as the transcript records them: no batch or fast-mode discounts, no tool-use fees, and a transcript Claude Code did not keep is not counted.

## `scripts/sync-public.py` (APS-65)

Both sides are read from refs, never a work tree or an index: the source is this repo's `origin/main` (fetched first; fixed in the script, not read from the config), and the config itself is read there, so an uncommitted edit of `public-sync.json` changes nothing; the report compares against `public_ref` of the public repo (`origin/main`, fetched first), so "in step" means what is published, not an unmerged branch. A failed fetch is named: a report then exits 2 (`UNKNOWN`) instead of 0, and `--write` and `--reviewed` refuse. Every file of the source tree is published except `public-sync.json`, `.sync-source.json` and the public-only files (`CLAUDE.md`, `README.md`, `.claude/branch-name.json`); each `replace` rule (`from`, `to`, `paths` globs) rewrites only the files it names: the path of this repo in `rores/global/CLAUDE.md`, and the redactions of internal names in older intents (switch-test answer keys hold this repo's path byte for byte, so no rule touches them). The executable bit follows the source, and a mode difference is reported and fixed. Files the public tree tracks that the source lacks are deleted (deletes run before writes). A submodule or a symlink in either tree is refused. `.sync-source.json` records, for each public-only file, the internal commit it was last brought in step with (`--reviewed`); the report lists it again when the internal file changed since, the recorded commit is unknown, or the public file is missing while the internal one exists (missing on both sides is in step). `--write` and `--reviewed` refuse, writing nothing, on `main`, `master` or a detached HEAD, or on a branch that does not contain `public_ref`. `--write` also refuses on a public tree with uncommitted changes, through a symlink, where a file replaces a directory that still holds files that stay, or when a file to add or update matches a leak pattern: token and key shapes (GitHub, Anthropic, OpenAI, Plane, Google, AWS, Slack, private and PGP keys) and the internal names listed in the config. `--reviewed` runs in the tree `--write` left (hand edits may be uncommitted) and refuses unless the tree was last written from the same internal commit, so a review is always recorded against what was synced. `--write` exits 3 when public-only files still need their hand review. It never commits, pushes or merges; read its result with `git add -A && git diff --cached`, which shows new files too. Unexpected errors exit 2, never 1. Limits: the patterns catch known shapes and listed names, not every secret or internal fact, which is why the main session reads the diff before the public merge; a rule stated only in the internal `CLAUDE.md` reaches students only through the hand review.

## `gates/session-gates.py` (APS-66, APS-67, APS-69, APS-70, APS-71)

A PreToolUse hook (Bash, Edit, Write, NotebookEdit, MultiEdit, Read, Grep, Glob) and a SubagentStop hook for every session. A call that carries `agent_id` comes from a subagent: the hook records the git work trees it touches (its cwd, file and path arguments, `cd`/`pushd` and `-C` targets, absolute paths) under the session in `$TMPDIR/session-gates-<uid>/` (one file per session, changed under `flock`), and decides nothing. The main session's Read, Grep and Glob get no decision. For the main session: (1) a repo with `.claude/branch-name.json` (`pattern` a regex string, `example` optional, `no_push` an optional list of branches no push may reach or delete: bare `git push` on one, `HEAD:main`, `x:main`, `--delete main`, `:main`, and `--all`/`--mirror` while one exists locally) refuses a branch it creates, renames to or pushes whose name does not match: `git checkout -b/-B/--orphan/--track`, `git switch -c/-C`, `git branch <name>`, `git branch -m`, `git worktree add` (`-b`, or the branch git names after the path when no commit-ish is given), `git push` (each named ref that is a local branch or has a `:dst`, and bare `git push` or `HEAD` as the current branch; deletes, tags, `--all`/`--mirror`, option values and names with `$` are skipped) and `dispatch.py new <repo> <branch>` (its `--task`, `--check`, `--allow`, `--forbid` values skipped); (2) while a subagent that touched a tree has not stopped and called within 2 hours, an Edit, Write, MultiEdit or NotebookEdit of a file in that tree, or a changing command run there (git add, commit, merge, rebase, reset, checkout, switch, stash, pull, am, cherry-pick, revert, restore, rm, mv, apply, clean, `branch -d/-D/-m/-M/-f`, and `gh pr checkout`, `gh pr merge -d/--delete-branch` (a merge without it changes only the remote); `stash list/show`, `apply --check/--stat` and `clean -n` are reads), is refused, naming the agent and `session-gates.py clear <id>` (or `clear --all`) for an agent that died; (3) a Bash command that an active shared-memory lesson's `match:` regex finds in its first 20,000 characters (quotes around the value are dropped, as memory's `check.py` does; a lesson with an invalid regex is skipped), or for a lesson without `match:` that contains a backticked token of six or more characters from its `applies_when`, gets the lesson named once per session as context. Commands are read quote-aware over the whole text: heredoc bodies are dropped (any delimiter, quoted or `\EOF`; not `<<<`, not `<<` inside quotes, even on a later line of a multi-line string), line continuations are joined, each `$( … )` or backtick substitution counts as one word holding `$` (so its inner words are not the outer command's arguments, and a branch name with one is skipped), read to its own closing `)` through `'…'`, `$'…'`, double quotes, `${ }`, backticks, nested substitutions, `$(( ))`, `#` comments and `case` patterns (a pattern's `)`, its optional leading `(`, `;;`, `;&`, `;;&`, and `case`/`esac` after one), inside double quotes too; an unclosed one is kept in its word and the rest is read on, so a `;` or `&&` after it still splits (APS-70, APS-71). A `'` inside a double-quoted `${ … }` pairs in bash, pairs in dash only after the pattern operators `#`, `##`, `%`, `%%`, and is taken as literal in zsh (not verified: zsh is not installed here). A command with `$(` or `${` is read several ways and every command any reading finds is checked: the new scanner under each of those three `'` rules, and main's scanner as of APS-70 kept unchanged (`scan_end_main`), so a mistake in the new scanner can add refusals but never drop one that scanner made: main's reading runs first (a cap on recorded directories never drops its commands), and a fault in a new reading skips that reading only (APS-71). In a substitution, the new scanner keeps command position as a state (after `;`, `&`, `|`, `(`, a newline, a pattern's `)`, and after `then`, `do`, `else`, `elif`, `if`, `while`, `until`, `time`, `{` or `!` when those are themselves in command position); `case` and `esac` count only there, `;;` starts a pattern only at the parenthesis depth of an open `case` (so `for ((;;))` does not), and `#` after a subshell's or a pattern's `)` starts a comment. Commands inside a substitution are not checked (`echo $(git push origin main)` passes), redirections and leading shell keywords and wrappers (`if`, `then`, `do`, `{`, `!`, `time -p`, `env`, `command`, `exec`, `nohup`, `sudo`, `xargs`, `timeout [-s SIG] N`) are dropped, `$(( ))` arithmetic is no heredoc, and `;`, `&&`, `||`, `|`, `&`, newlines, parentheses and `#` comments count only outside quotes; `cd`/`pushd` carry within a subshell. `main` and `master` are never checked by the branch gate. A subagent's paths also count when they appear inside a quoted string (`python3 -c "open('/repo/x')"`; not a remote `host:/path`; at most 200 directories a call). Limits: an interpreter or a script that runs git passes; a `git pull` in the shared memory is refused while a subagent that read it runs; a write by a shell redirection or `sed -i` is not seen; a subagent's first call is what records its trees, so a change before that is not caught; the hook prints nothing on its own error and exits 0 (`|| true`).
