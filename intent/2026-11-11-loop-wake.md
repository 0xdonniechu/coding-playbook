# A one-prompt run whose session died is woken up, within caps, and the owner is told

Ticket: Plane APS-59. Source: the assessment of 2026-11-11 ("can the playbook run to the goal, the human only joining
after three failing rounds?"): the one gap left inside the loop is a session that ends without closing its run.

## Problem

A one-prompt run lives in its session. When that session dies (crash, systemd-oomd, HTTP 429 or a spent usage
quota, a closed window), the run stays open and nothing picks it up: the owner finds it hours later, by asking.

## Outcome

1. A systemd user timer runs `loop/loop-wake.py tick` every 10 minutes. For each open run whose session has been quiet
   for 30 minutes (its transcript and its subagents' files unchanged, no live session record marked busy), it forks
   that session headless: `claude -p --resume <old> --fork-session --session-id <new>`, in the session's own working
   directory and model, in the permission mode the Stop hook recorded, with a prompt that says what happened. The run
   is bound to the new session first, so the old one (if it is still open somewhere) is no longer held.
2. Caps: 4 wakes per run, a wait between wakes that doubles (30, 60, 120 min), the run's own time limit, and $50 of
   wake spend per day across all runs (design decision 2 of ambysto-1prompt): each wake reserves at most $20 of it (owner confirmed 2026-11-11)
   before it starts and passes that to the CLI as `--max-budget-usd` (a new number, flagged to the owner). When a cap is hit the run closes (`limit`) and the plan's Plane ticket gets a comment. Every
   wake also comments on the ticket, so the owner knows a headless session is working.
3. A run in a mode that asks before tool calls (`default`, `manual`, `plan`), or with no known mode, is never woken:
   a headless session there cannot get its permissions. A woken session always runs under 1prompt's boundary settings.

## Constraints

- Light: one new file, standard library only, reusing loop-stop.py's run lookup and Plane comment.
- HARD: it spends money unattended and forks sessions. The main session (Opus 5.5) builds it; hard-reviewer
  (Fable 5.2) reviews it.
- Never two writers on one session: the fork has its own id; the wake runs in a systemd unit named after the run.

## Success

Self-test with a fake `claude`, `systemd-run` and `plane.py` covers each rule (wake, every reason not to wake, each
cap, the binding, the spend ledger). A live proof: a real session bound to a run, left dead, is woken by `tick` and
carries the run to done.

## Decisions

- Here, not in ambysto-1prompt: the wake reads this repo's run file, which the public repo does not know; the beads
  driver there stays its own design.
- A fork, not a plain resume: safe whether the old process is dead or idle, and the transcript of the old session
  stays as it was.
- The timer is installed by hand once per machine (`loop-wake.py install`), not by `install.py`.
