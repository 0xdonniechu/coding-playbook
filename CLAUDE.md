# coding-playbook: which model does which job in Claude Code, and the skills and scripts that go with it

## What it does
The four subagents (builder, reviewer, hard-reviewer, transcriber), the global instructions, nine skills (`starter-kit`, `handoff`, `sdlc`, `teardown`, `orca-worktree-setup`, `agent-team`, `create-skill`, `secrets`, `whats-next`), the builder dispatch and sdlc check scripts, a one-command model switch and the switch test kit, the agent-guard hooks, the owner-token guard and the save-it hooks, the Plane and progress-diagram scripts, the one-prompt loop (`loop/loop.py` and its Stop hook), the session graph hook, the owner time log report, plus a check script and an installer. Standard library Python only. Every session on every machine follows these files, so a wrong rule rates HARD work as EASY or lets an unreviewed change through.

## Verify
- `python3 scripts/check.py`: agent frontmatter and pinned models, `hard-reviewer` body equal to `reviewer` body, `rores/global/CLAUDE.md` matches the pins, the starter-kit template's sections, skill frontmatter, `settings-defaults.json`, and the self-tests of `dispatch.py`, `sdlc-check.py`, `switch-model.py`, `saveit/saveit-hook.py`, `plane.py`, `progress-diagram.py`, `graph/graph-hook.py` (a fake `ambysto-graph` and `systemd-run` on a scratch repo: refresh, skip with no change, lock, failing or killed jobs keeping the old graph, the start lines), `loop/loop.py` and `loop/loop-stop.py` (the run file and the Stop hook on scratch repos and plans: gaps and failing checks block, reviewer verdicts recorded and required, done, two fails, three check rounds, idle, the time limit, the ticket comment, never trapping a session), plus `install.py --settings` registering the session hooks once each and a refusal writing nothing (scratch HOMEs).
- `HOME=$(mktemp -d) python3 scripts/install.py` then `--check` under the same `HOME`: installs and reports no drift, without touching `~/.claude`.
- A change to an agent's behaviour: start a new session, run the agent once on a known diff, and record what it returned in the PR.
- A change to a skill's steps: run it once in a fresh agent on a scratch repo, given only the skill, and record where it had to guess.

## HARD: the main session does it directly, then hard-reviewer
- The model choice and switching: the "Current choice" line, any agent's `model:` or `effort:`, `scripts/switch-model.py`.
- Task rating (EASY / MEDIUM / HARD), the review loop, who may commit or merge, the honesty rules.
- The reviewers' checklist and their PASS/FAIL rule.
- `scripts/dispatch.py`: the task contract a builder works to, which `hooks/agent-guard.py` enforces, and the task parser in `scripts/sdlc-check.py` that `--task` reads it from.
- `graph/graph-hook.py`: the session graph. SessionEnd only starts `refresh <top>` detached (a transient `systemd-run --user` service with `MemoryMax=4G` and `RuntimeMaxSec=900`; a failing `systemd-run` starts nothing; without systemd, as on macOS, a new process session), because Claude Code gives a SessionEnd hook a short budget; the job holds `<git dir>/progress-diagram/refresh.lock`, skips when HEAD, `git diff HEAD` and the untracked names are as last time, and replaces `overview.md` and `architecture.html` only after both were written whole, so a failing tool keeps the old graph and records the error in `session-graph.json`. A state whose refresh failed, or whose job died twice, is not tried again until the work tree changes. SessionStart prints two lines naming the files, the commit and how far HEAD moved, never the overview itself. It writes only into the git folder, always exits 0, and runs with `|| true`.
- `loop/loop.py` and `loop/loop-stop.py`: the one-prompt run. Done rests on evidence: the Stop hook judges with `sdlc-check.py converge --checks`, which runs each task's `check:` commands through the shell once nothing else is missing, each in its own process group that a timeout kills whole (900 s each, 1500 s for all, the hook has 1800 s), and the third round with a failing check closes the run (`checks`; the count starts again at `resume`). The SubagentStop mode (`loop-stop.py subagent-stop`) records the first PASS or FAIL word of every run of an agent whose type ends in `reviewer` in the run's `reviews`; `loop.py pass` is refused unless the last one is PASS, and done is refused on a last FAIL, on a reviewer FAIL that has no `loop.py fail`, or with no PASS when a Proof item names a review. Limits, on purpose: a verdict is not tied to a task, and the run file is a plain file the session could edit; this guards against haste, not against cheating. `start --hours <n>` (default 12) sets a time limit the hook enforces. A run closed by ask, two fails, idle, a limit or checks is commented once on the plan's `Plane <KEY-N>` ticket (`plane.py` beside the judge, detached). A session in permission mode `default` is told once that it will wait at unknown commands. While a subagent of the session runs in the background (the Stop input's `background_tasks`, type `subagent`) the hook gives no decision and counts nothing, 10 stops in a row at most, so waiting for a reviewer never closes a run as idle (found by the first live run, 2026-11-11); a background shell is not waited for, because one that never ends would leave the run open with nobody told. A check's output stays in the run file: the ticket comment names the task and the command only. `loop.py start <plan>` writes `<git dir>/1prompt-run.json`, bound to the session that started it (`CLAUDE_CODE_SESSION_ID`); `~/.claude/1prompt-runs/<session id>` points the hook at it wherever the session's cwd is. The Stop hook blocks that session's stop while `sdlc-check.py converge` lists a gap, a proof result is a FAIL or a task's review FAIL has no later PASS; it closes the run as done only on the judge's own PASS verdict (a crash, a timeout or other output is never done), after the second FAIL of one task (`loop.py fail`), on `ask` or `stop`, after 3 stops with no change in HEAD, the content of the work tree, the plan or the verdicts, or after 40 stops held. An error inside the hook lets the session stop (a judge failure holds it, bounded by the breakers), and its command ends in `|| true` (exit 2 from a Stop hook would keep it going). Limits: one run per work tree and one open run per session; the breakers count stops, not time; untracked files are hashed up to 1 MB each.
- The installer's writes to `~/.claude` (backups, the marker block, which also takes over a block left by an earlier `coding-playbook` or `claudecode-guide` install, skill folders, `hooks/saveit`, `hooks/loop` and `hooks/graph`, and with `--settings` the entries of `rores/global/settings-defaults.json` and the session hook entries in `settings.json` (PreToolUse, SessionStart, PreCompact, Stop, SubagentStop, SessionEnd; an entry already there is brought to this repo's timeout), each appended once beside any other hooks; it never sets the model and never deletes).

## MEDIUM: builder builds, reviewer reviews
- Builder and transcriber wording that changes what they do or when they stop; the template's sections; a skill's steps or stop points; `scripts/check.py`; `scripts/sdlc-check.py`.

## EASY: transcriber or builder, no review
- README wording, typos, examples that do not change a rule.

## Rules
- Models are pinned to full model IDs (`claude-opus-5-5`), never aliases. A model change edits every agent file, the "Current choice" line and the README in one PR (`scripts/switch-model.py` does it in one command).
- The body of `hard-reviewer.md` is the body of `reviewer.md`: edit `reviewer.md`, then copy its body; `check.py` fails otherwise.
- Universal only: no project's paths, commands or names in `rores/agents/`, `rores/global/` or `skills/`. Three exceptions: `rores/global/CLAUDE.md` names this repo's own folder (`~/work/0xdonniechu/coding-playbook`) where it points at `dispatch.py`, `hil-report.py`, `loop/loop.py`, `progress-diagram.py`, `plane.py` and the switch-test kit; its Tools section names the owner's local tools (`ambysto-saveit`, `ambysto-graph`, Plane, `ambysto-1prompt`'s design) because every session needs to know them (owner instruction 2026-11-10: load the existing tools, one step at a time); it tells a session to skip a tool that is not installed; and "The loop" names `ambysto-memory` and `ambysto-1prompt` as the repos where GitHub keeps merges with the owner.
- Nothing secret: no keys, tokens, hosts or ids.
- The builder's task contract is enforced by `hooks/agent-guard.py`. The main session still reruns the contract's checks and runs `sdlc-check.py converge` before review.
- `hooks/agent-guard.py` and `hooks/autonomous-settings.json` are copied from `ambysto/1prompt` at the commit `hooks/pin.json` names: change them there, copy them here, update the pin.
- Git: English only; the `0xdonniechu` account (check with `gh api user --jq .login` before the first PR of a session; do not switch accounts); branches `feat/...` or `fix/...`, never a push to `main`; only the main session commits, pushes, opens and merges PRs: it merges on its own under the global rule (this repo's merges publish nothing) once the whole Verify passed on the branch and the review passed (a change of model, rating or review rule needs the owner's approval first), then deletes the branch and its worktree (owner decision 2026-11-11).

## Read when
- Changing the switch script: `scripts/switch-model.py --self-test` runs it on a scratch copy of this repo.
- Adding a skill: add its name to `SKILLS` in `scripts/check.py`.

## Session state
`HANDOFF.md` (gitignored) holds only where the current goal stands. Plans, decisions and dead ends go in files, not in the chat.
